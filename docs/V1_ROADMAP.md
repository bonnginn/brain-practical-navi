# βから正式版1.0へ

2026-10-02の方針：実習終了後、数日で既存教材の仕上げを行い、約1年間の開発休止に備える。未公開改善の統合、重大な不具合、運用・復元・再開記録を優先し、新機能・精密分節・ブロック再設計は広げない。[長期休止時の運用と終了条件](MAINTENANCE_AND_RESTART.md)。公開と1.0表記への変更は管理者判断で、休止や公開を実施済みとは扱わない。

2026-09-30現状確認。PR #42の教材・分節・集計改善は公開βへ反映済み。正式版1.0の公開は別途の管理者判断が必要。公開確認と残る脳梁境界は[再開メモ](RESUME_SUMMARY.md)を参照。

## 今後の基本方針

機能を増やすことより、現在の教材で「観察する・自分で探す・位置と働きを説明する・答えを確かめる」が迷わずできる状態を磨く。日本語、断面と3Dの同時比較、共通の操作体系を中心に据える。実習日別のコースや新しいまとめページは作らない。

### 優先順位と完了条件

| 優先 | 次に取り組むこと | 完了の目安 |
| --- | --- | --- |
| 1 | 公開βを実習で使い、実際に困った操作・説明を集めて修正 | 初回利用でも脳表・断面・復習へ進める。画像を覆うUI、断面とスライダーが見えない配置、戻り先を失う操作を優先して解消 |
| 2 | 構造同定と四択の教育的な説明を磨く | 自分で探す→必要時のヒント→着色して答え合わせが明確。正誤解説は機能・形態・位置関係と選んだ誤答の違いを説明し、実装上の事情を前面に出さない |
| 3 | 表示・説明・クイズの重大な食い違いを修正 | 左右欠落、明らかな別構造の混入、機能や回路方向の誤りなど、学習を誤らせる問題を優先。微小な境界の粗さは別管理 |
| 4 | 実機・少人数試用の指摘を反映し、1.0の収録範囲を確定 | 学習を妨げる重大な既知不具合を解消し、試作と制限を整理。管理者の判断を得て正式公開 |

### UIで維持すること

- 一番見たい画像・3Dを優先し、断面はスライダーまで初期画面に収める。必要な文字の読みやすさを保ちながら余白・文字サイズ・操作欄を調整する。無理にすべてを一画面へ詰めない。
- 断面方向は画像側で切り替え、左側は構造選択に使う。長い説明や補助ガイドは必要時に開く。部位ごとのアトラス注意書きを繰り返さない。
- 指定された入口の紹介文、教育目的、公開β、利用上の注意の文言は維持する。学習Homeと入口を分け、出典は利用条件とは別に見つけられる状態を保つ。
- 日本語・英語、キーボード操作、狭い画面、既存の教材機能を維持する。今後の変更も公開版へ自動で反映せず、対象を確認してから公開する。

### 外部教材・動画の扱い

UBC / UTHealth等の公式教材へ、関連する観察画面から少数の通常リンクでつなぐ。実物を回す、切断・露出の順序を示す、血管や脳神経を標本上で追う内容を優先する。何を見てほしいかを短く添え、出典を示す。外部動画の転載や無断の切り抜きは行わない。

立体的位置の自由な比較は既存3D、名称や機能の確認は静止画と短文を使う。長い講義や3D録画を大量追加しない。回路の伝播表示は現状を基点とし、さらに説明が必要なら、全体の位置図と断片を組み合わせた短い解説動画を検討する。既存の試作動画は確認後に採否を決める。

### 公開βで運用中：個人を追跡しない四択集計

四択の**各選択肢が選ばれた割合**を回答後に棒グラフで示す。復習の入口から管理者を含む閲覧者が、回答せずに全問の集計を確認できる。専用Workers/D1とアプリ側を公開運用中。問題別結果は回答後、全問一覧は開いた時に取得する。[1〜5の実装記録](V1_CANDIDATE_2026-09-27.md)、[集計設定手順](QUIZ_STATISTICS.md)、[最新の公開状態](RESUME_SUMMARY.md)。端末内誤答履歴とは別で、過去の履歴は送らない。

完了した四択セットの「問題数・正解数」別の延べ回数も公開した。個人の成績履歴を作らず、同じ得点の回数だけを保持する。[集計設定と配備結果](QUIZ_STATISTICS.md)。

- 集計単位は問題IDと問題の改訂版。氏名・学籍番号・メール・ユーザーID・端末識別子・セッションIDを収集せず、個人の成績や回答の組合せを追跡しない。
- 公開中の保存は問題版・選択肢別の回答数と、問題数・正解数別の完了回数に絞る。個別履歴や時刻は保存しない。受信基盤が通信上扱うIPやヘッダーも確認し、完全匿名と断定しない。
- 「人数」ではなく「延べ回答件数」と明記する。再挑戦による偏りは残る。画面内の二重送信は抑えるが、重複排除のための個人追跡はしない。
- 構造同定は自己確認であり、答え表示を正解とみなさない。まず四択のみを対象とする。
- 四択回答時に集計し、送信内容と目的を短く示す。通信失敗でも学習機能はそのまま使える。
- 受信API、ログ・保持期間、閲覧範囲を運用中も確認する。端末内履歴を送らない旨と、集計の送信を日英で区別して説明する。入口の指定文言は変更しない。

### 当面保留すること

- ピクセル単位の完全分節、微小な塗り残し・浮遊片の網羅的な修正。教材理解に影響する箇所だけをまとめて直す。
- ブロック標本の追加試作の反復。実習スケッチ等が得られてから、現実的な切り方で代表標本を一つ作り直す。目標は「不透明・無着色の形態で分かり、あとから着色で確認できる」標本。側脳室では上・横の露出と海馬との位置関係を重視し、構造だけの完全抽出や単純な直方体切断を完成形としない。
- 視放線等の精密な新規分節、根拠不足の保留クイズの復活、大規模MRI教材、臨床機能、新規脳表モデル。

### 人の協力が必要なこと／開発側で進めること

人の協力が必要なのは、実習での使い心地、実標本スケッチ、手元のタッチ端末・Safari/PWAでの試用、専門家確認の手配、最終公開判断。専門家監修はβの必須条件ではなく、1.0の必須条件にするかは未決定。未監修を監修済みとは扱わない。

開発側では、再現できる不具合の修正、日英説明と問題の整合、必要な資料照合、外部リンクの導線、変更箇所のブラウザ確認を進める。未確認の解剖境界は推測で完成扱いせず、独立した改善を止めない。

検証は変更に対応するものに絞り、全件試験は統合・公開の区切りで行う。失敗を直したらまず対象を再検証する。文書のみの更新でアプリ全件試験は行わない。開発量ではなく、教材として改善した点を短く記録する。

## 1.0の到達点

主要構造を、位置・形・機能の説明とともに観察し、復習まで自力で進められる教材にする。全構造の精密分節は要件にしない。学習内容を先に示し、部分分節・模式表示の区別を必要箇所へ短く添える。

| 段階 | 作業 | 終了条件 |
| --- | --- | --- |
| 1 | 読込・更新、操作、狭い画面とキーボードの問題を修正 | 代表的な学習操作を最後まで行える。実機で未確認の範囲は別に残す |
| 2 | 位置・見分け方・主な機能・関連構造の説明と英訳を整える | 表示・説明・クイズが食い違わず、学習者が観察に使える |
| 3 | 脳表→断面→回路→復習の入口と学ぶ順序を用意 | 次に何を観察し、何を説明できればよいかが分かる |
| 4 | 少人数の試用で操作・説明の問題を集める | 学習を妨げる主な問題を修正し、再確認する |
| 5 | 正式機能・試作・制限を確定して公開準備 | 重大な既知不具合がなく、収録範囲が明確。管理者が公開を承認する |

人の協力が必要：物理タッチ端末・Safari/PWA実機の操作、学生等の試用、専門家確認の手配と最終公開判断。専門家監修はβ必須条件から除外済み。1.0の必須条件にするかは未決定であり、開発側で勝手に追加しない。専門家確認を受ける場合は主要な取り違え、回路方向、機能説明、クイズ正答を優先する。

## 試用の短い手順

名前・学籍番号・成績等を集めず、操作上の問題と教材の分かりにくさだけを記録する。説明を先回りせず、困った時点を観察する。

1. 教育用の入口からHome、脳表へ進み、構造を選び、その説明を開く。
2. 断面と3Dを見比べ、隣接する断面へ移動し、構造の着色を切り替える。
3. Papez回路を一段ずつ進め、観察画面から回路説明へ戻る。
4. 関連クイズを解き、解説と観察で答えを確認する。
5. 読み込み直し、狭い画面、キーボードで困る点がないか確かめる。

記録は「端末/ブラウザ」「操作」「期待」「実際」「再現するか」で十分。専門家評価や学習効果を測った扱いにはしない。

## 1.0を止めない項目

微小な分節外縁・小片、視放線の実標本分節、ブロック再設計、保留8問の復活は後続候補。ブロックは実習スケッチを得てから代表標本を一つ仕上げる。分節を細分化する作業や全件試験の反復を進捗の代わりにしない。
