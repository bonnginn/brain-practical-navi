## 休止前の終了条件

1. 未公開分をまとめて型検査、通常／Pages build、配布権利表示と対象操作を確認する。統合試験は区切りに一度行い、失敗修正後は対象から確認する。
2. 管理者の公開判断後に公開し、公開Origin・日英・旧PWAからの更新を確認する。β表記を勝手に1.0へ変更しない。
3. 公開コミット、生成済み配信物、Workerソースと設定、D1の集計、ローカル証拠を復元できる状態で保存する。秘密情報・復元bookmarkはGitへ入れない。
4. 物理タッチ/Safariの未確認、専門家確認、微細分節、スケッチ待ちのブロック再設計を残件として明示する。学生の意見がないことを品質保証としない。

## 稼働を続けるものと停止できるもの

| サービス | 休止中の役割 | 障害・停止時 |
| --- | --- | --- |
| GitHub Pages | 静的な本教材の配信 | 公開リポジトリ・Pages設定と最終成功のActionsを確認。再配信は公開操作として扱う |
| Worker/D1 | 選択肢別・完了セット別の匿名カウンター | 教材と復習は継続できる。集計取得の失敗表示から手動再取得。自動再送・回答キューは作らない |
| Google Forms | 任意の意見回答 | 教材の起動条件ではない。回答者URLと公開範囲を確認し、編集・回答シートURLを配信物へ入れない |
| Cloudflare Web Analytics | 公開サイトの利用集計 | 四択集計とは別。アカウントの設定と使用量を確認する。localhostでは送信しない |
| 外部標本動画 | wet brainの補足 | 動画が開けない場合は公開元の教材ページへ進む。外部教材を転載・再配信しない |

アカウントを削除したり、サービスを自動停止したりする設定は追加していない。Cloudflareの**実際の契約プランと請求設定**は管理画面で確認が必要。無料枠を恒久的な無料保証や費用上限とは扱わない。[Workers制限](https://developers.cloudflare.com/workers/platform/limits/)、[D1制限](https://developers.cloudflare.com/d1/platform/limits/)を再確認する。通知・上限の設定、課金プラン変更は管理者の判断で行う。

## 集計の保存と止め方

匿名性の設計は[集計資料](QUIZ_STATISTICS.md#データと通信)を参照。延べ回答・延べ完了セットであり、利用人数や初回成績ではない。

10月2日は公開GETだけで選択肢集計28行、得点集計0行を `work/freeze-checkpoint-20261002/public-results.json` と `public-session-results.json` へ保存した。これは公開される集計値の写しで、**D1全体のSQLバックアップや復元試験ではない**。

完全なSQL保存は専用D1の設定ディレクトリで、認証済みWranglerを使う。新規に資格情報を公開コードへ入れない。公式の[export手順](https://developers.cloudflare.com/d1/best-practices/import-export-data/)ではexport中にDB要求がブロックされるため、実行は利用の少ない時間に行う。

```sh
npx wrangler d1 export brain-practical-quiz-statistics --remote --output=../../work/freeze-checkpoint-20261002/quiz-statistics-backup.sql
```

このコマンドは手順として保存したもので、今回未実行。SQL保存後は新しいローカル検証DBへ読み込み、二つのカウンターテーブルの行数と合計を照合してからバックアップ完了とする。本番D1を検証用に上書き・削除しない。SQLや設定は別の安全な保存先へコピーし、Git公開対象にしない。

集計だけを止めたい場合は、アプリのbuild設定 `VITE_QUIZ_STATISTICS_URL`（Pagesではリポジトリ変数 `QUIZ_STATISTICS_URL`）を空にして再配信する。これは公開変更であり指示が必要。古いPWAは以前の送信先を持つため、即時の受信停止も必要ならWorkerを停止するが、D1は保存し削除しない。記録済みのWorker/D1以外には触れない。

## ローカルと公開を復元する

- ソースは最終公開コミットとローカル開発HEADの両方を残す。`package-lock.json` も維持する。`npm ci` を使い、再開時に一括で最新版へ更新しない。
- 公開候補の通常buildとPages buildは `work/october2-freeze-preview` と `work/october2-freeze-pages` に保存する。配信物をローカル分節の原本として使わない。
- `work/` とignoredの設定は、リポジトリとは別にフォルダーごとバックアップする。原画像・図・可逆差分を削除して容量を削らない。OneDrive上の存在だけを別媒体の復元確認と同一視しない。
- 公開のロールバックは独立したcheckoutで最終公開コミットをbuildし、確認後に配信する。開発checkoutを古いmainで上書きしない。
- PWAは教材とデータの版を揃えるため、古いタブがある間は旧版を保持する。編集データを書き出した後、同じ公開サイトの全タブ／インストールアプリを閉じて開き直す。利用者の保存データを消すための一律キャッシュ削除は案内しない。

## 再開時の順序

`git status`・ブランチ・HEADと[再開メモ](RESUME_SUMMARY.md) → 公開版とローカルの差 → Pages/集計/外部教材の稼働 → 重大な不具合 → 具体的な学生の指摘 → 人手なしで改善できる説明・UI。精密分節、新しい教材形式、ブロック再設計は、その後に必要性を判断する。既存の保留小片を根拠なしに再調査しない。

既存の未コミット `CONTRIBUTING.md` は今回の候補に含めない。最終公開判断、請求設定、D1完全バックアップ、別媒体復元、実機試用が未完了なら、そのまま残件として示す。
